## Description

The extraction in P4 claims byte-equivalence; nothing today can falsify that claim
(`cli/tests/integration.rs` is assert-based, no `insta`/snapshot dependency exists). Build
the baseline first, from a fixture repo covering every renderer branch.

## Location

**Files:** `cli/tests/golden.rs` (new), `cli/tests/fixtures/golden/` (new — fixture builder +
captured goldens), `cli/Cargo.toml` (mech — dev-dep if a snapshot crate is chosen).

## Changes

- Deterministic fixture-repo builder (real `git init` — required, or gitignore-aware walkers silently apply no rules; see `daemon.rs:2295` and measurement §4).
- Capture stdout + stderr + exit code per command into checked-in golden files.
- Normalization: ULIDs and timestamps substituted by a documented stable mapping — **substituted, never deleted** (a deleted field can't regress).

## Acceptance Criteria

- [ ] Fixture contains ≥1 each of: rich turn, bare turn, git turn, epoch gap, undo turn, `skipped` entry, `withheld` entry, imported turn, duplicate-id pair collapsible by `same_revert`.
- [ ] Goldens captured for `log`, `log --all`, `log --json`, `log --explain`, `status`, `diff <t>`, `blame <path>`, `blame <path>:<line>`, `show <t>`, `show <t> --prompt`, plus one failing invocation per command (unknown id) — stdout, stderr, and exit code each.
- [ ] Three consecutive runs over a freshly built fixture produce byte-identical goldens (determinism proof).
- [ ] `UPDATE_GOLDEN=1 cargo test --test golden` regenerates; without it, a one-character change to `fmt::SEP` makes ≥1 golden fail (RED-proven, then reverted).
- [ ] Harness runs with the daemon stopped and spawns none.

## Verification

`cargo test -p agentrec --test golden` → 21 passed (new file);
`cargo test --workspace -- --test-threads=3` → **baseline + P1/P2 deltas + 21 passed, 0
failed, 1 ignored** (plan's 392 assumed the stale ladder). A deliberate `fmt::SEP` mutation →
golden binary reports `≥1 failed` with a printed byte diff; restored after.

## Notes

- **Edge case (from plan, load-bearing):** a fixture built in a non-git tempdir silently
  disables all ignore rules — the harness must `git init` (this exact trap inverted a probe
  result once, measurement §4).
- **Stale-build trap (repo memory):** rapid neuter/restore RED-verify cycles can false-fail
  on a stale cargo artifact — rebuild between steps, verify source with `grep`.
- **Plan-exit ACs this phase feeds:** every P3 golden byte-identical at the plan's FINAL
  commit (not just after P4) — goldens are the byte-equivalence instrument for the whole
  plan.
- **The goldens' CAPTURE point is the P2+P3 integration commit, not the P3 branch — decided
  2026-07-29.** P3's fixture must contain an imported turn (AC1), whose serialization only exists
  once P2 adds `imported`/`files_complete` to `TurnRecord`, and whose `log` rendering changes again
  when P2's "partial file list (imported)" marker lands (P2 AC7). So goldens captured on the P3
  branch alone cannot satisfy the plan-exit AC above. Two alternatives were rejected: seeding the
  imported turn *without* the P2 fields fails AC1 (a record carrying neither field is not an
  imported turn, and it recreates the P1 failure shape of a fixture agreeing with nothing real),
  and a `VERIFY-LEDGER.md` regeneration carve-out loosens an AC for convenience. Capturing at
  integration satisfies the AC literally and tightens instead. One deliberate regeneration happens
  at that merge, affecting the `log*` and `status` goldens; it is expected, not a regression.
- P4 consumes these goldens; do not weaken or regenerate them in P4 to make extraction pass
  (ratchet).
