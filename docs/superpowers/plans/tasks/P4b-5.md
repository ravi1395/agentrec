## Changes

### 1. Parent spec §Deep module 1 — four signature amendments

The parent spec is the higher-authority document, so these amendments are deliberate and each must
state *why* the code won:

| Spec says | Reality | Rationale to record |
|---|---|---|
| `health() -> Result<RepositoryHealth, RepoError>` | `health(budget: u64)` | Budget comes from config; the view deliberately holds no config. Re-coupling would also disturb P5's `status --json` AC surface. (decision 8) |
| `list(..) -> Result<.., RepoError>` | `-> Result<.., CursorError>` | Strictly more precise. (decision 8) |
| `diff(..) -> Result<Page<FileDiff>, RepoError>` | `-> Result<DiffResult, DiffError>` | `Page<T>` has no turn-level slot, so the golden-pinned header `turn <id> · <tool> · N files` has no carrier — and a fileless turn's empty page makes it unproducible. (R20/R26) |
| `blame(..) -> Result<BlameResult, RepoError>` | `-> Result<BlameResult, BlameError>` | `RepoError` is a single `Io(String)`; reproducing `<path> has only N line(s)` through it would require prose crafted in core, violating decision 9 and misfiling a user-input error as I/O. (R13) |
| `recall(..) -> Result<Page<MemoryHit>, RepoError>` | `-> Result<RecallPage, RecallError>` | A bare `Page` drops `capped` (F3), `store_corrupt` (F10), and `store_empty` (PD3), each of which drives real adapter behavior. (decision 10) |

Every one **adds** precision or information — these are ratchet-ups, not loosenings. Say so
explicitly in the amendment text; the house rule is that a ratchet only tightens.

### 2. Parent spec — the `agentrec_log` MCP row (decision 12)

The spec promises `agentrec_log` yields "≤200 turn **summaries**" *and* that read tools "mirror the
Phase 2.0 `--json` contracts exactly … same typed values, one serializer". Under decision 5 those
are irreconcilable: `log --json` is full `TurnRecord`s, MCP summaries are `TurnSummary`. Amend the
row to state that `agentrec_log` mirrors `list()`'s **summary** contract, and defer a full-record
tool or parameter. (This also aligns with the spec's own "prompt contents never in generic
summaries" rule.)
