## Description

Capture five new goldens against **current** code: three `recall --json` states and two human
`recall` empty states. They are the instrument for AC2 and AC11 in later tasks.

## Location

**Files:** `cli/tests/golden.rs` (edit — add tests + fixture seeding),
`cli/tests/fixtures/golden/*.golden` (create — five files).

**Explicitly zero production files.** `git diff --stat` on this commit must show no file under
`cli/src/` or `agentrec-core/src/`.

## Changes

Add five golden tests following `golden.rs`'s existing harness shape (stdout + stderr + exit
sections, hand-seeded fixture, real `git init`):

| Golden | Command | Fixture state |
|---|---|---|
| `recall_json_hits` | `recall <matching-query> --json` | memory store with ≥2 fresh pinned memories, one matching |
| `recall_json_no_match` | `recall <non-matching-query> --json` | same non-empty store, query matches nothing |
| `recall_json_empty_store` | `recall <any> --json` | initialized repo, no memories ever recorded |
| `recall_human_no_memories` | `recall <any>` | empty store → **stderr** `no memories yet — agentrec remember "<fact>" --from <file>`, exit 0 |
| `recall_human_no_match` | `recall <query>` | non-empty store, no fresh match → **stdout** `no fresh memories match "<query>"`, exit 0 |

The last two are the pair that `RecallPage::store_empty` exists to preserve — in `--json` mode both
emit `[]` (the json branch returns before the distinction is drawn), so the human pair is the only
place the difference is observable.

**Fixture-identity constants (R23, required by `golden.rs`'s documented stable-mapping
discipline):** every id, timestamp, and content hash reaching a golden must originate from a named
`const` in the test file — never from `memory::remember`'s real id generator or `SystemTime::now()`.
Follow the existing `RICH_TURN_ID`/`BLOB_APP_BEFORE` pattern: bind literals, seed `memory.jsonl` by
hand, and grep-verify the captured golden against the same constants. Do **not** add a pattern-based
normalizer — `golden.rs`'s module doc explains why (it would swallow a wrong-but-well-formed id).

## Notes

- **Edge cases:** a fixture built in a non-git tempdir silently disables every gitignore-aware
  walker — `build_fixture` must `git init` (this trap inverted a probe result once, and `golden.rs`'s
  module doc calls it out).
- The harness is non-TTY, so `fmt::should_color` yields false; no ANSI reaches a golden.
- Do not run a daemon in this harness — every command here is read-only over a hand-seeded fixture,
  which is what makes the goldens timing-independent (AC5 of P3).
