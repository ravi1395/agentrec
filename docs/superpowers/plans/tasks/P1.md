## Description

Build the importer's read half and prove the Phase 2.0 hard stop on the real corpus before
anything consumes imported history. Emits a classification report and writes nothing, so it is
mergeable inert. This phase retires the scariest unknown in the spec's table: "historical
imports cannot reconstruct safe before/after state".

## Location

**Files:** `cli/src/importcmd.rs` (new), `cli/tests/import_claude.rs` (new),
`cli/tests/fixtures/import/claude/` (new fixtures), `cli/src/main.rs` (mech — verb + `mod`).

## Changes

- Streaming JSONL parse over `~/.claude/projects/**/*.jsonl` (never load a file whole).
- Session→root mapping by transcript `cwd`; sessions outside the target root counted and skipped.
- Sidechain exclusion by **path** (`subagents/`) **and** field (`isSidechain: true`).
- File-entry extraction from `Edit`/`Write` `toolUseResult`; `Bash`/`Task` results name no files (recorded as opaque, never inferred).
- Before-bytes ladder, per entry, first hit wins: **T1** `toolUseResult.originalFile` or `create` op → **T1.5** `~/.claude/file-history/<sessionId>/<hash>@<vN>` (resolved via `snapshot.trackedFileBackups[path].backupFileName`) → **T2** git blob at latest commit ≤ turn timestamp → **T3** `None`.
- **T2 is detected, not resolved, in this phase.** Resolution needs a per-session git object read path (open the repo at `cwd`, replay `git log --until <turn ts>`) — the measurement doc explicitly scoped that out. P1 classifies an entry T2 when its path is git-tracked in the session's repo; actually reading the blob lands in P2. The gate measures **session importability**, which does not depend on T2 resolving, so this keeps P1 at three substantive files without weakening the gate.
- `agentrec import claude --dry-run [--source <dir>] [--json]` prints per-tier counts, per-file skip counts, session totals, peak RSS.

## Acceptance Criteria

- [ ] `agentrec import claude --dry-run` over the real `~/.claude/projects` corpus reports **≥90% of top-level sessions importable**; the printed denominator is top-level sessions, not all `.jsonl` files, and is **re-measured at run time** — the corpus is a rolling ≤30-day window (`cleanupPeriodDays` default 30; oldest transcript measured exactly 30.0 days on 2026-07-28), so the 2026-07-18 baseline (1266/1277) is a shape reference, never an assertable count.
- [ ] The dry-run report includes the **fidelity figures** (spec decision 8): % of extracted entries at T1, T1.5, T2-candidate, T3, and per-session opaque-call share; the figures land in a VERIFY-LEDGER row. No fidelity threshold is asserted — the founder sets one from this first measurement.
- [ ] The command creates or modifies **zero** bytes under `.agentrec/` — asserted by a recursive dir digest taken before and after the run.
- [ ] Every extracted file entry carries exactly one tier tag `T1|T1.5|T2|T3`. Fixture entries resolved at T1 and at T1.5 have `sha256(resolved before bytes)` byte-equal to the known-good pre-edit content; T2 entries are reported as **candidates** (path git-tracked in the session's repo), never as resolved bytes. No tier ever yields bytes it did not read from a source.
- [ ] A `subagents/agent-*.jsonl` file and an inline `isSidechain: true` line are both excluded, counted under `skipped_sidechain`, and produce zero top-level turns.
- [ ] A file whose every line is malformed reports one skip per line, exits 0, and does not abort the run or the other files.
- [ ] Peak RSS over the 515 MB corpus is printed and **< 500 MB** (measurement baseline: 37 MB).
- [ ] A transcript missing a required field (`cwd`, `toolUseResult`) fails the CI canary loudly with the field name, not silently importing less.

## Pinned decisions (2026-07-29, before execution — binding, do not re-litigate)

Ground-truthed against real `~/.claude` data on this machine before any code was written.
These close ambiguities an advisor review flagged as likely to silently determine whether the
gate number means anything.

1. **`--source` layout.** `--source <dir>` defaults to `~/.claude` and must contain sibling
   `projects/` and `file-history/` directories (mirroring the real layout) — NOT just a
   `projects/`-equivalent dir. T1.5 resolves as
   `<source>/file-history/<sessionId>/<backupFileName>`, where `backupFileName` is read
   **verbatim** from `snapshot.trackedFileBackups[<path>].backupFileName` (confirmed shape:
   `"<hex>@v<N>"`, e.g. `bb6db0439755b9fa@v1`) — never recomputed or hashed by the importer.
   Test fixtures mirror this: `<fixture_source>/projects/...` + `<fixture_source>/file-history/...`.
2. **Sidechain path shape (confirmed on-disk):** `<projectDir>/<sessionId>/subagents/agent-<id>.jsonl`
   — exclude by the literal path segment `/subagents/` AND by `isSidechain: true` on any line;
   either signal alone is sufficient to exclude.
3. **"Importable" predicate (pins AC1's numerator/denominator — the definition floats nowhere
   else in this doc, pin it here):**
   - **Denominator:** every `*.jsonl` file directly under `~/.claude/projects/<project>/`
     (one level — NOT under a `subagents/` subdirectory), regardless of whether every line
     parses. Re-measured at run time (rolling ≤30-day window).
   - **Numerator ("importable"):** a denominator session counts as importable iff (a) it is
     not entirely excluded as a sidechain-only file (i.e. not every line has `isSidechain:
     true`), and (b) the run classifies it to completion without hitting the AC8 loud-failure
     path (a required field missing on a line that needs it) — a session with some malformed
     lines (AC6) still counts importable if at least one line parses and the session
     completes; a session with zero file-entries but at least one opaque tool call (Bash/Task)
     still counts importable (opaque calls are legitimate, not failures).
   - Record this exact predicate text in the VERIFY-LEDGER row next to the measured percentage
     — a gate number whose definition floated is the first thing a skeptical review attacks.
4. **AC6 vs AC8 — do not conflate (different failure classes, different counters):**
   - **AC6 (malformed JSON line):** a line that fails to parse as JSON at all. Skip + count
     under a generic bucket (e.g. `skipped_malformed_line`); process continues; command exits 0.
   - **AC8 (schema drift — parseable, but missing a field the entry type requires):** a line
     that parses as JSON but lacks `cwd` (session-level) or `toolUseResult` (on an entry that
     is structurally a tool-result needing it) — this is a **named, distinct counter** (e.g.
     `skipped_missing_field { field: "cwd" }`) surfaced loudly (printed to stderr and present
     in `--json` output with the field name) so schema drift is visible — this does not
     require nonzero process exit; the distinguishing requirement is a **named** signal,
     not lumped into the generic AC6 bucket. Test both with separate fixture files.
5. **AC7 RSS unit.** `libc::getrusage` `ru_maxrss` is **bytes on macOS, KiB on Linux** — verify
   which one before converting to the printed `rss_peak_mb`; a wrong platform constant passes
   or fails this AC for the wrong reason on CI's Linux leg. Use `#[cfg(target_os = "macos")]` /
   `#[cfg(target_os = "linux")]` to pick the divisor, and unit-test the conversion function
   itself (not just the printed value) so the two platforms don't silently share one path.
6. **AC3 zero-bytes digest must use a tempdir root, never this repo's working tree.** The
   production daemon (`agentrec record`, watching the main tree) actively writes `.agentrec/`
   here; a before/after digest around a real-corpus run in this repo's own tree will move for
   reasons unrelated to import. Build the digest helper against a tempdir (optionally
   `agentrec init`-ed first) and reuse it unchanged for the plan-exit re-run.
7. **Fixture independence (AC4).** Fixtures are **hand-authored synthetic transcripts** —
   never copied lines from any real `~/.claude/projects` corpus (this repo is public,
   Apache-2.0; real prompts may carry secrets). Expected `sha256` hashes for T1/T1.5 fixture
   content are computed with `shasum -a 256` (or equivalent) **outside** the importer code,
   and fixture authorship is a separate task from implementing the T1/T1.5 resolver — the same
   agent authoring both would make AC4 self-confirming if both share the same misunderstanding
   of the `backupFileName` convention.
8. **`--json` for this command is local to `import claude`'s own output shape** — do not stand
   up P5's shared serializer early; that is out of scope here.
9. **Test-only seams** (e.g. an env var or flag to point `--source` at a fixture dir) must be
   `#[cfg(debug_assertions)]`-gated per the global constraints above — verify with
   `strings target/release/agentrec | grep <seam-name>` prints nothing on a release build.
