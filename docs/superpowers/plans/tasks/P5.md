- **Pre-existing overlap:** `status --json` already exists (shipped in the ignore-rebuild

  `RepositoryView`'s serializer, not that the flag is new.
- **Plan-exit ACs this phase completes:** this is the LAST phase — after it, run the plan's
  "Final acceptance — plan exit" section in full (all 9 checkboxes, orchestrator-verified,
  then a binding skeptical-reviewer round in an isolated worktree). Parse-only import gate
  does not count as retired; the fidelity VERIFY-LEDGER row must exist.
- **Amended 2026-07-30 (P4b-5, R27) — the empty-case literal.** This file's original
  `{"files":[]}` predates `DiffResult`'s design (P4b-2); `diff` does not yet emit `--json` at
  all (that flag is this phase's own scope), so the corrected literal above is derived, not
  observed, from `agentrec-core/src/view.rs::DiffResult` as it actually shipped: fields
  `turn_id: String`, `tool: Option<String>`, `total_files: usize`, `files: Page<FileDiff>`, in
  that declaration order (`serde_json` emits declaration order — see the precedent at
  `agentrec-core/src/record.rs::TurnRecord` and `view.rs::MemoryHit`). The literal above uses
  the actual `diff_fileless_turn_prints_the_header_alone_exit_0` fixture
  (`cli/tests/integration.rs`), which has `tool: Some("claude")` — a fileless turn, not a
  toolless one. For a genuinely **bare** (toolless) turn, this codebase's established
  convention for `Option<String>` fields that are usually absent (`TurnRecord::tool`,
  `MemoryHit::reason`) is `#[serde(skip_serializing_if = "Option::is_none")]`: the `tool` key
  is **omitted from the object entirely**, never emitted as `"tool":null`. Whoever implements
  this phase's `#[derive(Serialize)]` on `DiffResult` should follow that precedent for
  consistency with the rest of the CLI's `--json` surface. This is a literal correction, not a
  loosened AC — the AC's substance ("empty is data, not an error, exit 0") is unchanged and is
  what P4b-2's AC8 already pins at the `RepositoryView` layer.
