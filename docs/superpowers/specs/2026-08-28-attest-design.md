# agentrec attest — passive attestation over the recorded work

Date: 2026-08-28
Status: draft — founder-confirmed decisions 1–9 below; implementation plan drafted
(`docs/superpowers/plans/2026-08-28-attest-plan.md`), not yet chunked or executed.
Owner: Ravi
Companions: `PROBLEM.md` (the accountability thesis this extends), `PROTOCOL.md`
(untouched by v1 — see decision 9), `IMPLEMENTATION.md` (AC register — attest ACs land
there per phase), the claimd repo (`~/Projects/claimd`, archived — see "Lessons from
claimd", which is a normative part of this spec).

## One paragraph

attest makes "the agent says it's done" checkable without making anyone do paperwork.
Tests are the claim language — a claim is derived from a test, never hand-authored.
Evidence is captured passively from work agentrec is already recording. A criterion
counts as CONFIRMED only when an independent replay (clean worktree, pinned commit,
scrubbed env) says so. Humans sign off only on things a test cannot check, in one
sitting, judging evidence the tool already gathered. The output is an attestation
report per change: criteria, verdicts, and provenance chains from prompt to diff to
test run — the concrete form of PROBLEM.md's "accountability infrastructure" thesis,
and rung 3 of its ladder, reachable without vendor-signed emission because we attest
our own replay verdicts, not vendor records.

## Lessons from claimd (normative — the rejected-approaches register)

claimd (TypeScript, `~/Projects/claimd`) proved the protocol and disproved the
interface. Each lesson below is binding on this design; violating one re-opens a
measured failure.

1. **Hand-authored claim recipes are a bug surface bigger than the code they verify.**
   claimd's dominant REFUTED cause was malformed `--cmd`/`--match` recipes (agentrec's
   own ledger: "7 replay refutations this round were all claim-cmd bugs, zero code
   defects"). REJECTED: any design where a human or agent writes a replay command or
   match regex per claim. Replay recipes are GENERATED by framework adapters.
2. **Permanent-refutation semantics applied to typos poisons the ledger.** claimd's
   REFUTED was unamendable and re-declaration was "dodging", so recipe typos became
   permanent founder-owned debt. REJECTED: one undifferentiated failure verdict.
   Verdicts split (decision 4) and only `claim-false` is permanent.
3. **Active ceremony loses to passive capture.** Same founder built both tools; the
   passive recorder became beloved dogfood, the declare/evidence/verify treadmill
   became "insufferable". REJECTED: any step the agent or human must perform whose
   only purpose is feeding the trust system. Evidence capture rides work that already
   happens.
4. **Hand-globbed staleness scopes rot into a treadmill** ("66 claims STALE").
   REJECTED: `--stale-on` style manual scoping. Scope is measured (coverage), and
   staleness self-heals at explicit run moments.
5. **Per-item human attestation queues become debt** ("17 DECLARED awaiting manual
   attestation"). REJECTED: per-claim interrupts. Human review is batched,
   evidence-first, and split blocking/fyi.
6. **What claimd got right, kept verbatim:** append-only event log with deterministic
   fold; CONFIRMED only from independent replay, the author's own run is evidence
   never a verdict; two-tier gate trust (advisory local / authoritative CI that
   trusts nothing it didn't verify this run); split-token CI so no job both executes
   repo-authored code and holds a write token; manual kind for un-testable criteria.

Also rejected, from this design round:
- **claimd v2 evolution** — two daemons, two stores, a seam at the join, and the
  interface baggage above. Clean break instead (decision 7).
- **A third tool reading both stores** — worst maintenance surface.
- **Graphify/static scope for v1** — founder chose coverage (decision 5): static maps
  miss dynamic dependencies (fixtures loaded by name, shell scripts, runtime
  dispatch), and a missed dependency is a silently un-rechecked regression — the one
  unforgivable failure for a trust tool.
- **Daemon-executed replays** — violates the recorder's watcher-only promise
  (decision 6). The daemon never executes repo-authored commands.
- **Importing `.claims/` history** — clean break (decision 7).
- **Implicit attestation from observed usage** — auto-sign-off without an explicit
  human confirm rots trust; usage evidence may PRE-FILL a card, never close it.

## Founder decisions (confirmed 2026-08-28, this conversation)

1. attest is an **agentrec subsystem** (`agentrec attest …`), not claimd v2, not a
   third tool. One product story: record + prove.
2. **Tests are the claim language.** Claims are derived from framework-native test
   identities via adapters emitting structured verdicts. No claim DSL exists.
   *Mechanism amended by founder ratification 2026-08-31 (the original
   `--message-format=json` channel was measured to carry no per-test data
   on stable — Review findings item 1):* discovery via per-target
   `--list`; single-test verify via a staged pipeline (build → `--list`
   membership precheck → target-scoped run, verdict from the summary
   line's counts, never bare exit code); bulk capture via ONE
   adapter-owned parser of libtest's per-test output lines,
   fixture-versioned, failing closed to a `parse_failed` evidence flag —
   one parser per adapter, never a per-claim recipe (lesson 1 holds).
3. **Evidence capture is passive**, joined to agentrec turn records: every captured
   test run references the `turn_id` it happened inside, chaining prompt → diff →
   test run → verdict.
4. **Verdict taxonomy:** `claim-false` (test fails on clean replay; permanent),
   `recipe-invalid` (test missing / build broken / harness error; retryable,
   auto-filed, no escalation), `flaky` (replays disagree; tracked statistically).
5. **Coverage-based scope.** Per-test executed-file sets recorded under
   instrumentation are the staleness scope. Spike (plan phase 1) decides granularity
   economics; the sanctioned fallback if per-test cost is prohibitive is
   suite-level coverage with coarser staling — still measured truth, never a static
   guess. When unsure, stale MORE (over-rechecking wastes background time;
   under-rechecking ships a regression).
6. **Middle-path execution.** The daemon only maintains the stale list (note-taking —
   its existing job). Test execution happens at explicit moments: any `attest`
   command, the gate, or an opt-in foreground worker. The daemon gains no code
   execution capability.
7. **Clean break from claimd.** Repo archived as-is; no history import; empty attest
   ledger. This spec's lessons section is the surviving artifact.
8. **Attestation UX:** (a) tests-over-manual bias — the tool proposes test skeletons
   to shrink the manual queue; (b) evidence-first card review (`attest review`,
   y/n/s single-key flow); (c) PR-checklist sync as a later phase; (d) self-usage
   evidence pre-fills cards, never closes them; (e) every manual item is `blocking`
   or `fyi`, and `fyi` never nags.
9. **PROTOCOL.md is untouched in v1.** Attest wire formats are documented in a new
   `ATTEST-FORMAT.md` (draft status, explicitly unstable) until the subsystem earns
   a protocol section. The frozen PROTOCOL 1.0 gains nothing until then.
10. **(added 2026-08-31) Renaming a test carries its claim history forward
    under a stable id.** `ClaimId` is a stable surrogate minted at first
    derive (machine-scoped ULID, the turn-id scheme), NOT an identity
    hash — an identity-derived key cannot survive a rename, since test
    identity includes the fn name. The fold maintains the
    identity→claim-id mapping; rename detection is adapter-side
    (body-hash match within one derive run), fold applies the
    already-resolved result. No hand-authored rename annotations (lesson
    1 holds).

## Review findings (2026-08-28 rounds; dispositions updated 2026-08-31)

Five rounds of adversarial plan review (`docs/superpowers/plans/
2026-08-28-attest-plan.md`) measured real gaps against the decisions above.
Each was reported rather than silently applied — an agent narrowing its own
founder-confirmed commitment unprompted is this repo's own recorded
"indistinguishable from dodging" line. Dispositions:

1. **Decision 2's original mechanism measured false → RATIFIED replacement
   2026-08-31.** The replacement channel is now written INTO decision 2
   above (the single copy — earlier review rounds kept a full duplicate
   here and the duplicate went stale, so this entry is deliberately just a
   pointer). Measurement record: plan Phase 1, Probe B.
2. **Decision 4's `claim-false` permanence collides with a measured live
   flake** (a recorded flaky test in this repo — named in plan Phase 4 and
   CLAUDE.md; a single-run verify would mint it PERMANENT claim-false).
   Disposition: constraint accepted; `attest verify` never writes
   `claim-false` from one run; plan Phase 4 owns the retry-and-compare
   policy and carries a falsifiable flaky-fixture AC. Not restated here.
3. **The daemon-purity invariant's enforcement mechanism was corrected
   twice, and one correction rested on a false premise since retracted.**
   Round 2 claimed clippy proves transitivity — false, clippy has no
   interprocedural analysis (fixture-verified). Round 4 then claimed
   clippy can't even deliver a per-site census because existing blanket
   `#![allow]`s would suppress it — measured false in round 5: those
   allows exist only in TEST code; zero production spawn sites sit under
   one. Settled mechanism (plan Phase 4, the single copy): clippy
   `disallowed-methods` entry + per-site allows, a census of direct
   production call sites, explicitly NOT a transitivity proof.
4. **Rename continuity → decision 10 above (added 2026-08-31).** The
   data-model consequence (stable surrogate `ClaimId`, not an identity
   hash) is in the decision text; mechanism in plan Phase 2/3.

## Architecture

One new store file plus reuse of everything agentrec already has:

```
.agentrec/
  attest.jsonl        # append-only attest event log (NEW; same append rules as log.jsonl)
  attest/coverage/    # per-test coverage maps, content-addressed pointers into objects/ (NEW)
  objects/            # existing CAS — evidence blobs (test output, reports) land here
  log.jsonl           # existing turn log — evidence events reference turn ids from here
```

Event kinds over `attest.jsonl` (state = deterministic fold, exactly like claimd's
surviving core, reimplemented in Rust):

- `derive`   — a test was discovered; claim created/updated (id = stable surrogate, decision 10)
- `evidence` — a captured run: structured result, output blob hash, HEAD, dirty bit, turn_id
- `verdict`  — an independent replay result: confirmed | claim-false | recipe-invalid | flaky-observation
- `stale`    — daemon-written scope hit: which claim, which file write triggered it
- `human`    — card review outcome: y/n + note, or waive, for manual-kind items
- `manual-declare` — the only hand-authored event: an un-testable criterion's text + blocking|fyi

Claim states (fold output): `DERIVED → EVIDENCED → CONFIRMED | CLAIM-FALSE |
RECIPE-INVALID(retryable) | FLAKY`, with a `STALE` overlay that queues re-verify and
drops on the next verdict.

Components (all in the existing two-crate workspace):

- `agentrec-core/src/attest/` — events, fold, claim identity, verdict types. Pure;
  no process spawning in core.
- `cli/src/attest/adapter_cargo.rs` — discovery, result interpretation, and
  per-test replay invocation per decision 2's ratified channel. The adapter
  trait is the seam later adapters (node:test, jest, pytest) implement.
- `cli/src/attest/capture.rs` — the passive tap: `agentrec attest run -- <cmd>`
  wrapper, plus recognition of test invocations arriving through the existing hook
  path; writes `evidence` events joined to the open turn.
- `cli/src/attest/replaycmd.rs` — `attest verify`: clean worktree from pinned commit
  (git archive extraction, the gate-proven pattern — never `worktree add` into the
  live repo), scrubbed env, adapter-run, verdict event.
- `cli/src/attest/coverage.rs` — instrumented run orchestration (cargo-llvm-cov),
  map persistence, staleness predicate the daemon consults.
- daemon: one addition — consult the coverage maps on file-write events it already
  sees, append `stale` events. Note-taking only.
- `cli/src/attest/reviewcmd.rs` — the card flow (`attest review`), evidence
  rendering via existing view/diff machinery.
- `cli/src/attest/gatecmd.rs` — advisory gate v1 (fold + exit code + report);
  authoritative CI gate is a later phase and carries claimd's split-token workflow
  design when it lands.
- `agentrec attest report --range <base>..<head>` — the attestation bundle:
  markdown + JSON, criteria × verdicts × evidence links × provenance (turn → prompt).

## Invariants (inherit agentrec's, plus)

- `attest.jsonl` is append-only; corrections are appended events. No rewrite class
  exists for it in v1 (adding one requires a decision-register entry).
- The daemon never executes repo-authored commands. Enforced as a census of
  direct spawn call sites (plan Phase 4's clippy `disallowed-methods`
  mechanism — `daemon.rs` production code carries no exemption, so a
  direct spawn added there reds the build), explicitly NOT a transitivity
  proof and NOT "no attest code in the daemon binary" (everything is one
  binary; the earlier by-construction wording was false and is retired —
  correction history in Review findings item 3).
- An author's own run can never produce CONFIRMED — `evidence` and `verdict` are
  disjoint event kinds written by disjoint code paths.
- `recipe-invalid` never blocks a gate by itself; it queues a retry and surfaces in
  `status`. Only `claim-false` and missing-blocking-human-attestation block.
- Manual attestation is always an explicit human keypress; observed usage only
  pre-fills.
