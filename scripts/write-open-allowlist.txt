# Reviewed production write-open call sites — the allowlist for
# `bash scripts/check-write-opens.sh`. See that script's header for why this
# is a file keyed on `path::fn` rather than marker comments or line numbers.
#
# FORMAT:  <path>::<fn>  <expected-line-count>  # <rationale>
#
# The count is the number of matched write-open LINES in that function (an
# `OpenOptions` builder contributes one per flag, e.g. `.create(true)` plus
# `.append(true)` == 2). It is deliberately part of the key's contract: a new
# unguarded write added inside an already-reviewed function is the single most
# likely way this gate gets bypassed, and only the count catches it.
#
# Every entry must match at least one site — an entry matching none is a
# VIOLATION, not a no-op, because that is how a broken scanner announces
# itself instead of silently passing.
#
# FOUR RATIONALE CLASSES (see agentrec-core/src/fsguard.rs's module doc):
#   [guard]     `fsguard::is_nonregular` is called on the same path, in the
#               same function, before the open.
#   [excl]      `create_new(true)` — O_CREAT|O_EXCL fails with EEXIST on ANY
#               pre-existing inode including a FIFO, and never blocks. The
#               path is a freshly-minted tmp name in either case.
#   [upstream]  Unreachable with a non-regular file in hand because a guarded
#               READ earlier on the same path already refused it. Weaker than
#               [guard]: it depends on a caller-side invariant. Each one is
#               spelled out.
#   [nonexist]  Reached only when the path does not exist, so no FIFO can be
#               sitting there. `exists()` follows symlinks, so this class is
#               sound for the BLOCKING hazard only; it is not a symlink guard.
